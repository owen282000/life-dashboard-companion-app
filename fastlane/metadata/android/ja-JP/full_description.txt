ヘルスコネクトのデータとスクリーンタイムを、AndroidスマートフォンからHome Assistant、MQTTブローカー、または自分のWebhookへ、スケジュールに沿って送信します。アカウントは不要です。開発者がデータを受け取ることはなく、アプリは入力された送信先にだけ送信します。広告も分析ツールもありません。自分のサーバーが必要です。

ヘルスコネクトに書き込むアプリなら、どれでも使えます。Samsung Health、Google Health（FitbitとPixel Watch）、Garmin Connect、Oura、Withingsなどです。

新しいレコードだけでなく、編集や削除も送信されます。変更を送信できない場合は、ペイロードにその旨が示されます。

Home Assistant
- MarketplaceまたはHACSからLife Dashboard統合をインストールし、表示されるQRコードをスキャンします。YAMLもブローカーも不要です。
- 34タイプのうち26タイプとスクリーンタイムがセンサーになります。履歴の各日がその日付で長期統計に入ります（おおよそ直近1年分まで）。
- 受信（統合が必要）：Home Assistantにある体重計や血圧計の測定値を、オンにしたタイプごとにヘルスコネクトへ書き込めます。

Webhookと自分のサーバー
- JSON POSTを受け付けるサーバーならどれでも使えます。n8n、Node-RED、自作のスクリプト、または別途用意するセルフホスト版のLife Dashboard Stack（PostgresとGrafanaダッシュボード付き）などです。
- 各レコードを完全な形で1つまたは複数のURLへ送信します。URLごとに署名シークレット（HMAC-SHA256）とカスタムヘッダーを設定でき、クライアント証明書（mTLS）にも対応しています。
- 受信側はペアリングコードを表示できます。スキャンすると、アドレスとシークレットが入力されます。
- 再試行に加え、未配信の同期をサーバーが復旧するまで保持する送信キューがあります。

MQTT
- MQTT Discoveryにより、34タイプのうち25タイプとスクリーンタイムが1つのデバイスのセンサーとして表示されます。TLSとログインは任意です。

送信するデータ
- 34タイプ。それぞれに専用のスイッチと権限があります。歩数、距離、カロリー、睡眠（ステージ付き）、心拍数、心拍変動、体重と体組成、血圧、血糖値、VO2 max、エクササイズ、栄養、周期記録など。
- 各レコードには、書き込んだアプリの情報が含まれます。日別合計はヘルスコネクト自身が計算するので、スマートフォンとウォッチの両方が記録した散歩も1回として数えられます。
- Webhookまたは統合への過去データ送信：30日分から5年分、またはヘルスコネクトにあるすべてのデータまで送れます。

スクリーンタイム
- アプリごとの使用時間を、健康データと並べて送信します。日の区切りは自分で選べます。
- すべてのアプリ、一部を除くすべてのアプリ、選んだアプリのみ、から選べます。除外したアプリの情報がスマートフォンの外に出ることはありません。その時間は1日の合計にのみ含まれます。

送信タイミング
- 15分以上の間隔、または選んだ曜日の決まった時刻に送信します。休止時間帯も設定できます。
- ウィジェット（同期の状態）、クイック設定タイル（Life Dashboardを同期）、TaskerとMacroDroid用のインテント。

結果の確認
- 直近100件の配信のログ。失敗、Webhook、MQTTで絞り込めます。
- 送信前のJSONのプレビューと、送信先ごとのテスト送信。
- データのCSVまたはJSONファイルへの書き出し。

Life Dashboard Stackの読み取り専用MCPサーバーにより、自分で運用するAIモデルが履歴を読み取れます。アプリ自体にAIは含まれていません。

シークレットはスマートフォン上で暗号化されます。MITライセンスのオープンソースで、コードはGitHubで公開しています。

アプリは11言語に対応しています：日本語、英語、オランダ語、ドイツ語、フランス語、スペイン語、イタリア語、ポルトガル語（ブラジル）、アラビア語、ヒンディー語、簡体字中国語。

健康データの送信には、Android 9以降とヘルスコネクトが必要です（Android 14以降は標準搭載、Android 9〜13はGoogle Playのアプリ）。スクリーンタイムはAndroid 8.0以降で動作します。
